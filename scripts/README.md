# Profile cards

The images in the profile README live in `assets/` and are generated by `scripts/generate.mjs`.
Nothing needs to be installed: the script uses only Node 22.

## How it updates

`.github/workflows/update-profile.yml` runs every day (and on every push that changes the config or the scripts),
reads the GitHub GraphQL API, redraws the cards and commits them when something changed.
It can also be started by hand from the **Actions** tab ("Update profile cards" → "Run workflow").

By default it uses the workflow's own token, so only **public** data is counted.
To include private repositories, create a classic personal access token with `read:user` and `repo`
and save it as the repository secret `PROFILE_TOKEN`.

## Editing the content

Text, stack and links shown in the cards come from `profile.config.json` (name, role, tagline, "now" line,
stack groups, languages to hide). Edit it and push; the workflow redraws everything.

## Files

| File | What it draws |
|---|---|
| `scripts/lib/header.mjs` | Name, role, tagline and the "Now" line |
| `scripts/lib/stack.mjs` | Tech stack chips, grouped |
| `scripts/lib/activity.mjs` | Numbers, contribution calendar and languages |
| `scripts/lib/github.mjs` | API queries and the numbers (streaks, language shares) |
| `scripts/lib/svg.mjs` | Colors (same palette as eduardof.dev), sizes and shared helpers |

Every card exists in four versions: `wide`/`narrow` × `dark`/`light`. The README picks one with
`<picture>`: narrow below 600 px, and the theme that matches the viewer's GitHub setting.

## Preview without the API

```bash
node scripts/generate.mjs --fixture scripts/fixtures/sample.json
```

The fixture holds synthetic numbers. Don't commit `assets/` after a fixture run;
the next workflow run redraws them with real data anyway.
